# TG WS Proxy для iOS

iOS-клиент запускает то же Rust-ядро, что десктоп и Android, и отдаёт Telegram
локальный MTProto-прокси на `127.0.0.1`. Отдельный сервер для базового режима не
нужен.

> [!WARNING]
>
> Сборка **никем не проверялась на живом iPhone**. Она собирается в CI на
> macOS-раннере, Rust-мост покрыт тестами, но Swift-часть, фоновая работа и
> связка с Telegram нуждаются в проверке пользователями.
> [Сообщайте о найденном в Issues](https://github.com/danusha2345/tg-ws-proxy/issues).

## Чем iOS отличается от Android

В iOS нет аналога Android foreground service. Как только система усыпляет
приложение, TCP-слушатель на `127.0.0.1` закрывается и Telegram теряет прокси.
Обойти это можно двумя способами:

| Способ | Что даёт | Чего требует |
| --- | --- | --- |
| Network Extension (`NEPacketTunnelProvider`) | прокси живёт в отдельном системном процессе и переживает закрытие приложения | платный Apple Developer Program и entitlement `com.apple.developer.networking.networkextension` |
| Фоновый режим `audio` | приложение не усыпляется, пока проигрывает звук | ничего — работает с бесплатным Apple ID |

**Эта сборка сознательно сделана по второму пути**: пока прокси запущен,
приложение зациклено проигрывает неслышимую тишину. Аудиосессия создаётся с
`mixWithOthers`, поэтому музыка других приложений не прерывается. Плата за это —
повышенный расход батареи, поэтому в приложении есть действия для «Быстрых
команд», чтобы поднимать прокси только на время работы с Telegram.

Чего этот способ не умеет:

- прокси останавливается, если закрыть приложение свайпом из переключателя
  задач;
- при нехватке памяти система всё равно может выгрузить процесс;
- приложение с таким фоновым режимом не пройдёт ревью App Store (TestFlight —
  вопрос открытый).

## Установка

Готовых подписанных сборок нет и не будет: подпись — дело того, кто ставит.
Соберите IPA сами (см. ниже) или возьмите артефакт `TgWsProxy-unsigned-ipa` из
успешного запуска workflow **iOS** на вкладке Actions, затем подпишите любым из:

- **AltStore / SideStore** — бесплатный Apple ID, подпись живёт 7 дней и
  продлевается, пока доступен AltServer;
- **Sideloadly / iLoader** — то же самое с компьютера;
- **TrollStore** — постоянная подпись на поддерживаемых версиях iOS.

Network Extension и App Groups приложение не использует, поэтому проблем с
entitlements у бесплатного профиля быть не должно.

## Использование

1. Откройте приложение и нажмите «Запустить прокси».
2. Дождитесь состояния «Работает».
3. Нажмите «Подключить Telegram» и подтвердите добавление прокси.
4. Переключитесь в Telegram — приложение останется в фоне за счёт аудиосессии.

Прокси можно прописать и вручную: Telegram → Настройки → Данные и память →
Прокси → добавить MTProto-прокси:

- сервер: `127.0.0.1`;
- порт: из настроек приложения (по умолчанию `1443`);
- secret: значение из вкладки «Настройки» с префиксом `dd`.

Изменённые параметры применяются при следующем запуске прокси, поэтому вкладка
«Настройки» заблокирована, пока слушатель работает.

## Быстрые команды и автоматизация

Приложение отдаёт в Shortcuts три действия:

| Действие | Открывает приложение | Возвращает |
| --- | :---: | --- |
| Запустить TG WS Proxy в фоне | нет | `true`, если слушатель поднялся |
| Запустить TG WS Proxy | да | `true`, если слушатель поднялся |
| Остановить TG WS Proxy | нет | `true` при успешной остановке |

Рабочая схема автоматизации «Когда открывается Telegram»:

1. Запустить TG WS Proxy в фоне.
2. Если результат `true` — завершить.
3. Иначе запустить TG WS Proxy (с открытием приложения) и вернуться в Telegram.

Второй шаг нужен потому, что iOS иногда отказывается поднимать процесс под
фоновое действие. На «Когда Telegram закрывается» повесьте «Остановить
TG WS Proxy» — это и есть основной способ не сажать батарею.

Поддерживаются и deep links: `tgwsproxy://start`, `tgwsproxy://stop`,
`tgwsproxy://settings`, `tgwsproxy://logs`, `tgwsproxy://info`.

## Возможности

- Rust MTProto/WebSocket proxy на `127.0.0.1`;
- direct WebSocket, Worker/CfProxy и TCP fallback;
- несколько пользовательских Cloudflare Worker-доменов и настраиваемый пул;
- Fake TLS и masking upstream;
- генерация и хранение secret в Keychain (`AfterFirstUnlockThisDeviceOnly`);
- состояние, счётчики подключений, время работы и объём трафика;
- открытие Telegram и копирование `tg://proxy`;
- просмотр, очистка и отправка ротируемого лога;
- действия для «Быстрых команд» и deep links;
- интерфейс на русском и английском.

Чего в iOS-сборке нет по сравнению с Android: встроенного обновления с GitHub
Releases, постоянного уведомления и виджетов.

## Сборка

Нужны macOS с полным Xcode 15+ и Rust `1.85` или новее:

```bash
rustup target add aarch64-apple-ios aarch64-apple-ios-sim

git clone https://github.com/danusha2345/tg-ws-proxy.git
cd tg-ws-proxy
git checkout ios-port

cd ios
./build.sh device      # dist/TgWsProxy-unsigned.ipa
./build.sh simulator   # .app для симулятора
```

Xcode собирает Rust сам: фаза «Build Rust core» вызывает
`ios/scripts/build-rust-ios.sh`, который строит `crates/ios-bridge` под нужные
архитектуры и кладёт `libtgwsproxy.a` туда, откуда линкуется приложение. Ядро
всегда собирается в release — в debug прокси непригодно медленный.

Чтобы запускать на устройстве прямо из Xcode, откройте `ios/TgWsProxy.xcodeproj`,
выберите свою команду в Signing & Capabilities и поменяйте bundle ID на
уникальный.

## Что проверить

- подключение официального Telegram iOS к `127.0.0.1`;
- сообщения, фото, видео и большие файлы;
- Wi-Fi, мобильную сеть и переключение между ними;
- выживание прокси при сворачивании приложения и при выключенном экране;
- реальный расход батареи за час работы;
- автоматизацию «Быстрыми командами» на открытие и закрытие Telegram;
- direct WebSocket, Worker/CfProxy, TCP fallback и Fake TLS.

В Issue укажите модель iPhone, версию iOS, способ установки и приложите лог.
Лог отправляется кнопкой «Поделиться» на вкладке «Логи» — перед отправкой
убедитесь, что в нём нет вашего secret.

## Происхождение и благодарности

Приложение написано для этого репозитория, но опирается на разбор существующих
iOS-портов:

- [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy) — оригинальный
  проект;
- [mIwr/tg-ws-proxy-ios](https://github.com/mIwr/tg-ws-proxy-ios) (MIT) — приём с
  удержанием в фоне через беззвучное аудио и автоматизация «Быстрыми командами»;
- [reekeer/tg-ws-proxy-ios](https://github.com/reekeer/tg-ws-proxy-ios) и
  [amurcanov/tg-ws-proxy-android](https://github.com/amurcanov/tg-ws-proxy-android)
  — устройство сборки Rust под iOS и разбор режима Packet Tunnel;
- [MushroomSquad/tg-ws-proxy-ios](https://github.com/MushroomSquad/tg-ws-proxy-ios)
  — описание ограничений фона без Network Extension.

Код этих проектов не копировался: Swift-часть написана заново поверх нашего
Rust-ядра, поэтому вся ветка остаётся под MIT.
