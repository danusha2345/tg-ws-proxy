# Восстановление прокси — 30 октября 2026

## Подтверждённая причина

На подключённом Android-телефоне долгий WebSocket через Cloudflare получает
первые 16–32 KiB, затем перестаёт передавать данные. На той же конечной точке
Linux получает 1 MiB полностью. Небольшой MTProto handshake при этом проходит,
поэтому проверка req_DH сама по себе не выявляет зависание медиа.

Отдельный тест свежих HTTP-соединений, по 8 KiB на запрос с параллелизмом 4,
получил на телефоне 1 048 576 байт за 5,688 секунды. HTTP chunked encoding
в диагностическом клиенте разобран полностью; число относится к payload.
Наблюдение согласуется с
[описанным Cloudflare ограничением в сетях РФ](https://blog.cloudflare.com/russian-internet-users-are-unable-to-access-the-open-internet/).
Конкретный оператор/узел, применяющий ограничение, не устанавливался.

## Исправление

Rust 1.14.0 / Android 0.4.0 используют встроенный Worker с HTTP relay.
Отдельные запросы/ответы ограничены 8 KiB и используют свежие HTTP-соединения.
TCP-сессия Telegram сохраняется внутри общего SQLite-backed Durable Object;
каждая пользовательская сессия имеет независимые socket, seq/ACK и очереди.
Upload retry не дублирует запись; download retry повторяет неподтверждённые байты.
Входящие и исходящие буферы ограничены, простаивающие сессии удаляются.

Свой VPS не задействован. Legacy Worker `/apiws` сохранён для старых клиентов.
При сетевом таймауте TLS новый relay может попробовать HTTP/80; ошибка
сертификата переход не разрешает. Режим «Worker: только TLS» запрещает его.
Собственный Worker включён по умолчанию в публичных сборках по явному решению
владельца проекта; общий CF-доменный пул выключен по умолчанию.

## Проверки и границы

- Node-тесты Worker: idempotent open/upload, порядок и повтор download,
  лимиты chunk, запрет посторонних IP, изоляция сессий и idle cleanup.
- Rust-тесты: повтор частичного HTTP body без потери/дублирования данных,
  свежие соединения, запрет plaintext recovery при ошибке сертификата,
  однократная миграция настроек и сохранение пользовательского opt-out.
- Clippy с MSRV 1.89.0, Rust/JNI/desktop unit и regression tests проходят.
- Rust CI проходит нативно на Windows, Linux и macOS.
- Подписанный Android-кандидат 0.4.0 установлен поверх 0.3.1 с сохранением
  настроек. SHA-256 проверены; сертификат совпал с установленной версией.
- Пользователь подтвердил на реальном телефоне: фото и видео загружаются.
- На физическом Windows-компьютере и в мобильной сети отдельный тест
  ещё не проводился. Энергопотребление и длительная работа не измерялись.

## Следующий шаг: скорость

В текущем клиенте download в одной MTProto-сессии последовательный: один
HTTP-запрос на 8 KiB. Поэтому скорость зависит от RTT и установления TCP/TLS.
Проверить конвейер из нескольких коротких запросов с сохранением порядка,
ограниченным окном и повторами по seq. Увеличение chunk допускается только
после измерений и согласования размера с клиентом: старые клиенты принимают
не более 8 KiB, изменение серверного default нарушит их совместимость.
